# 第 7 步 · 渲染与自查

## 命令

整片按段缓存渲染：第一次全渲，之后改哪段只渲哪段，再无损拼接。

```bash
cd studio
export CHROME_PATH=<chrome-headless-shell 路径>      # 无显示器的机器需要
python3 ../scripts/seg_render.py <合成名> --timing src/episodes/<期>/timing.json --out out/<文件>.mp4
python3 ../scripts/seg_render.py <合成名> --timing … --out … --only 市场,业绩     # 只重渲这两段
python3 ../scripts/seg_render.py <合成名> --timing … --out … --audio             # 配音、音乐、音效改了
python3 ../scripts/qc.py out/<文件>.mp4 --out out/qc
python3 ../scripts/facecheck.py out/<文件>.mp4 --timing src/episodes/<期>/timing.json \
  --shots src/episodes/<期>/shots.json --faces src/episodes/<期>/faces.json --footage public/<期>/footage
```

## 机器检查

| 项目 | 标准 | 常见原因 | 怎么修 |
|---|---|---|---|
| 黑场 | 没有 ≥0.2 秒全黑 | 镜头没盖住它的时间段 | 加长镜头或调放慢倍率 |
| 闪帧 | 没有 1–2 帧的突变 | 镜头首尾带了相邻画面 | 取点往里收 0.3 秒 |
| 亮度突变 | 相邻帧亮度差不超阈值 | 片段内部有硬切 | 逐帧看那个片段，重新取点 |
| 画面停滞 | 没有超过 6 秒无变化 | 静态画面放得太慢、组件太少 | 换有运动的镜头，或中间加一次变化 |
| 响度 | −18 到 −14 LUFS，峰值不过 −1 dBTP | — | 调人声归一或音乐音量 |
| 压脸 | 无压脸镜头 | 组件盖在人脸上 | 写 `faceTo`、挪组件，或换镜头 |

## 人眼检查（机器过了也要做）

`qc.py` 会输出每秒一张的联系表。逐张看：

- 文字有没有重叠、出框、被裁掉
- 原片自带的字幕、台标、标题有没有露出来
- 组件有没有盖住人脸（包括路人）
- 画面上的大字是不是在重复口播
- 表情和口播情绪对不对
- 有没有只剩字幕的空画面（除非是有意留的呼吸段）

可疑的地方再抽全分辨率的帧放大看。问题记到**段和秒**。

## 返修（省时间、省算力的顺序）

1. **先出静帧**：排版类的修改，用 `npx remotion still src/index.tsx <合成名> out/x.png --frame=<帧号> --scale=0.4` 看一张图，几秒钟。确认对了再渲视频。
2. **只渲受影响的段**：`seg_render.py --only <段名>`，一段约一分钟。全片其余部分用缓存。
3. **只检查改过的段**：把那一段截出来跑 `qc.py`，不必整片重查；涉及人脸的再跑 `facecheck.py`。
4. 改了镜头片段（镜头表）要先重跑 `prep_footage.sh` 再渲对应的段；改了时间（重新对齐）要全部重渲。
5. 汇报时只说改了什么、验证结果是什么，不重复贴整片的检查输出。
- 镜头的问题先看那个片段本身的逐帧条带，不要猜。
- 同一个问题出现两次，把它写成一条规则加进 `docs/aesthetic-rules.md`。

## 三种状态分开记

机器通过、助手逐秒看过、用户认可，是三件事。**声音助手听不到**：音乐风格、音效、剪口是否自然，必须明确告诉用户需要他来听。

## 放行条件
两个检查都通过；联系表看过；已知瑕疵如实列给用户。

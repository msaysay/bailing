# 相框口播线 第 3 步 · 关键帧、出片、自查、交付

## 1. 先看关键帧（一分钟）

```bash
scripts/frame_render.sh "episodes/<期>" keys
```
得到 `04_成片/关键帧.jpg`：每段画面、每个贴纸出现后不久各一张，拼成一张联系表。**打开它，一格一格看**：

| 看什么 | 不对怎么办 |
|---|---|
| 贴纸、清单有没有压到脸 | 改 `side`，或换到人铺满且景别小的时候 |
| 卡片上的字有没有出框、被小圆挡住、挤成一团 | 字太多：删字或拆成两张卡 |
| 小圆里是不是人脸 | `meta.json` 的 `face` 量错了，重跑 `frame_ingest.py` 或手动改 |
| 素材和这句话搭不搭，主体有没有被字幕挡住 | 换素材，或给 `clip` 加 `from` 换一段 |
| 聚光的字有没有盖到人 | 每行缩到 10 个字以内 |
| 标题三行有没有挤 | 回第 2 步改标题 |
| 字幕有没有断在词中间 | 回 `script.txt` 在那句中间加逗号，重新对齐 |

改 `edl.json` → 再跑 `keys` → 再看，直到没问题。别带着已知问题去渲整片。

## 2. 整片渲染和自查

```bash
scripts/frame_render.sh "episodes/<期>" full
```
产物：`04_成片/成片.mp4`、`04_成片/qc/`（每秒一张的联系表）。四分半的片子在 4 核机器上大约二十分钟。

脚本最后会跑两个自查：
- `qc.py`：黑场、闪帧、停滞、响度。它会报一串「亮度突变」并写「机器检查：未通过」：人和纸白卡片之间是硬切，亮度本来就会跳，**只要突变的时刻都落在版式表里换画面的时刻，就是预期内的**。黑场、闪帧、停滞有任何一条才是真问题。
- `frame_check.py`：标题区和署名条有没有被动过、画面窗有没有黑场、该有人的时候人在不在。

然后**把 `qc/` 里的联系表从头看到尾**。机器只能查出明显的坏，查不出难看。

## 3. 封面

```bash
cd studio && python3 - <<'PY'
import json; p = json.load(open("../episodes/<期>/03_制作过程/props.json")); p["coverAt"] = <人表情好的那一秒>
json.dump(p, open("/tmp/cover.json", "w"), ensure_ascii=False)
PY
npx remotion still src/yuedu/index.tsx YueduCover "../episodes/<期>/04_成片/封面.png" --props=/tmp/cover.json
```
`coverAt` 是人物视频里的秒数：挑一帧眼睛睁开、嘴没张大的。出完看一眼。

## 4. 交付时要说清楚的

1. 成片在哪、多长、用的哪组标题。
2. 剪掉了哪几句。
3. 画面的来源：客户素材几段、搜来的几段（列出处，请用户确认能用）、生成卡片几张。
4. 哪些卡片是「示意」（数字不是真实数据），请用户确认能接受，或提供真实截图替换。
5. `frame_plan.py` 的「提醒」里没处理的那些，以及原因。
6. **机器验证不了的**：口型对不对、卡片出现得早还是晚、素材和话搭不搭。明说「这几样我只能看静帧，请你看一遍动态」。
7. 这期缺什么素材（哪几句话只能用卡片顶上），下次可以让客户顺手拍。

## 5. 用户提了意见之后

- 只针对这一期：改 `edl.json`，重新 `keys` → `full`。
- 以后每期都适用：同时写进 `brands/yuedu/rules.md`。
- 是错字：改 `script.txt` 重新对齐；专名加进 `brands/yuedu/glossary.txt`。
- 想换署名：`brands/yuedu/speaker.json`。
- 想动相框本身（底图、标志、位置、颜色）：先跟用户确认是不是真的要改，这是全品牌的事，不是一期的事。

## 放行条件
`frame_check.py` 通过；`qc.py` 没有预期外的问题；联系表从头到尾看过；第 4 节的七件事都向用户说了。

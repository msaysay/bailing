# 音乐工具（musiclab）

给视频选配乐、对齐、调音量，并出一页并排试听。和剪辑流程分开，单独测；测好了再接回去。

现在是第一版。能做的事：从约 1450 首可商用曲子里选出 3 首，算好从曲子哪里开始放、怎么收尾、每一刻多大声，合成出来给人听。

## 三层结构

| 层 | 做什么 | 在哪 |
|---|---|---|
| 曲库 | 每首歌记：来源和授权、人工标签、听出来的数字（速度、重拍、段落、能量曲线、抢不抢人声）、统一的情绪维度 | `library/catalog.json`，`mlab/library.py`，`mlab/audio.py` |
| 需求单 | 一条视频想要什么音乐：类型、情绪、每段能量、关键节点 | `mlab/brief.py` |
| 匹配和编排 | 选曲、对齐、音量曲线、合成、试听页 | `mlab/match.py`，`mlab/render.py` |

每类视频的配乐规矩（在哪个节点做什么处理）写在 `rules/types.json`，可以直接改。看一眼：`python3 musiclab/ml.py types`。

## 怎么用

要 Python 3.10+、ffmpeg，以及 `pip install librosa soundfile numpy`。

```bash
python3 musiclab/ml.py sync                                    # 第一次：登记曲目目录（只登记文字，不下载）
python3 musiclab/ml.py brief 视频.mp4 --type talk -o out/某期     # 出需求单初稿
# 按内容改 out/某期/brief.json（见下面「需求单怎么填」）
python3 musiclab/ml.py match out/某期/brief.json                 # 选 3 首、合成、出试听页
python3 musiclab/ml.py rate out/某期 2 good --note "很合适"       # 听完打分
```

内容类型：`talk` 口播、`vlog` 生活 vlog、`teach` 老师分享、`finance` 新闻财经、`knowledge` 知识类。

有 `timing.json`（剪辑流程第 3 步的产物）时加 `--timing`，分段和每段文字直接从里面来。

`match` 的产物：

- `audition.html`：三个方案并排试听，带时间线图（谁在说话、配乐实际音量、对上了哪些节点）
- `方案N.mp4`：混好的成片（没画面时是 mp3）
- `方案N_bed.wav`：单独的配乐轨，已对齐、已调好音量，从视频第 0 秒开始。**接回剪辑流程用这个**
- `方案N_plan.json`：方案本身：曲目、授权和署名、分片、收尾方式、音量曲线、落在视频时间上的重拍表（给卡点剪辑用）

常用选项：`--no-credit` 只用不用署名的曲子；`--track 曲目id` 指定一首只做对齐；`--pool 20` 多听几首再挑。

## 需求单怎么填（给 AI 助手）

`brief` 出的初稿只听了声音：分段是按停顿切的，每段能量是按说话密度和音量猜的。**情绪和关键节点要看过内容的人或 AI 来补**，这一步决定配得好不好：

1. `want` / `avoid`：情绪维度的权重（0–1）。初稿是这类视频的默认值，按这一条的内容改。维度：明亮 bright、温暖 warm、平静 calm、推进 drive、俏皮 playful、紧张 tense、严肃厚重 serious、宏大 epic、阴暗 dark、好奇悬念 curious、科技感 tech。
2. `segments`：按内容重新分段也可以。`energy` 是这段想要的音乐能量（0–1），讲故事铺垫给低的，摆结果、喊口号给高的。
3. `moments`：关键节点，时间取那句话开口的那一刻。
   - `climax` 全片最高点：对齐音乐抬起来的段落，音量略推
   - `turn` 转折：对齐音乐段落交界，之前收半秒再进
   - `chapter` 换章节或换场景：对齐音乐段落交界
   - `point` 重点句：这句话期间音乐压到几乎听不见（给 `dur` 秒数）
   - `silence` 这里不要音乐（给 `dur` 秒数）
4. 一条片子节点不要多：一个 `climax`，两三个 `turn` 或 `chapter` 就够。节点越多，越没有一首歌能都对上。

AI 助手听不到声音，不要自己判断「好不好听」：把 `audition.html` 和成片交给用户听，用 `rate` 记下结论。

## 选曲怎么打分

第一轮只看文字标签，从整个库里筛出一批（默认 10 首），硬条件一票否决：不能商用、有人声（视频里有人说话时）、怪乐器、太短。第二轮把这批下载下来听一遍，四项加权：

| 项 | 权重 | 看什么 |
|---|---|---|
| 情绪贴合 | 0.45 | 曲子的情绪维度和需求单的 want / avoid |
| 结构对齐 | 0.25 | 音乐段落交界能不能对上节点、能量走势像不像、起点在不在重拍上、收尾干不干净 |
| 不抢人声 | 0.18 | 700–3500Hz 占比、鼓点重不重、电平稳不稳 |
| 速度 | 0.12 | 在不在这类视频的速度范围里 |

打过分的曲子，同类视频下次加分或减分；最近用过的略减分，免得每条都是同一首。

## 对齐和处理做了什么

- **从哪开始放**：把音乐的每个段落交界和视频的每个节点两两配对，算出一批起点，挑总分最高的。
- **收尾**：优先让曲子自己的结尾落在视频结尾（倒推起点，或在重拍上接一段曲子的结尾）。都做不到才淡出。
- **不够长**：在段落交界、重拍上循环，接缝 60 毫秒交叉淡化。
- **音量**：有人说话时压到人声以下约 20 个响度单位（各类型不同），提前 0.15 秒让开；停顿超过 1 秒自动抬起；开头钩子略响；每段按能量微调；转折前收半秒；重点句让开。
- **给人声让频段**：有人声时在 2.2kHz 压 3 分贝。

## 曲库和授权

| 来源 | 数量 | 授权 | 说明 |
|---|---|---|---|
| incompetech（Kevin MacLeod） | 约 1440 首 | CC BY 4.0：可商用，**要署名** | 目录自带情绪、乐器、速度标签。音频用到才下载 |
| 代码合成 | 8 首 | 没有版权问题，不用署名 | 原来 `music/` 里那 8 首 |
| 自己加的 | 随意 | 自己说清楚 | `ml.py add`：买的、自己做的、AI 生成的都从这里进 |

加自己的曲子：

```bash
python3 musiclab/ml.py add 我的曲子.mp3 --license "购买授权" --feel Bright,Uplifting
python3 musiclab/ml.py add ai生成.mp3 --source ai --license "Suno 付费版" --feel Calming
```

`--feel` 可用的词：Bright、Uplifting、Relaxed、Calming、Bouncy、Grooving、Driving、Mysterious、Intense、Somber、Mystical、Humorous、Epic、Action、Suspenseful、Dark。不给的话只凭听到的数字估情绪，比较粗。

给别人用时的规矩：

- 方案里用到要署名的曲子，`plan.json` 的 `license.credit` 就是那行署名，要放进视频简介。
- 音频文件不进仓库（`library/audio/` 已忽略），目录和分析结果进仓库。别人拿到后，没下载过的曲子用到时会自动下载。
- 不能确认可商用的曲子不要加进来。

## 参考画像：拿大 V 的成片当标准答案

AI 听不到声音，用户也很难凭感觉给出高标准的评价。所以标准从头部博主的成片里量出来：

```bash
python3 musiclab/ml.py ref add 小Lin说 --type finance -n 5     # 抓这个博主点赞最高的几条，拆出配乐，量
python3 musiclab/ml.py ref profile                            # 按方向汇总成参考画像
python3 musiclab/ml.py ref check out/某期                      # 我们的方案逐项对照大 V 的范围
```

做法：TikHub 按博主名搜抖音 → 只留声音 → demucs 把人声和配乐拆开 → 量。量的是：配乐覆盖全片多少、说话时比人声低多少、停顿处抬多少、第几秒进、中间留白几次、怎么收尾、鼓点重不重。同一把尺子也量我们自己的方案，所以能直接比。

要另装：`pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu && pip install demucs`。纯 CPU 拆一条大约等于片长。

这把尺子校准过：拿我们自己已知答案的成片走一遍「拆分再量」，音量误差约 1 分贝，覆盖率、留白、收尾方式都对。**速度和大小调量不准，不采用。**

已经量过的：

| 博主 | 方向 | 条数 | 说话时配乐比人声低 | 特点 |
|---|---|---|---|---|
| 小Lin说 | 新闻财经 | 14 | 中位 20 分贝（多数在 18–23） | 分段用音乐：覆盖约 82%，每分钟留白约 3 次；没人说话处抬 13 分贝；鼓点轻、音符稀 |
| 直男财经 | 新闻财经 | 12 | 中位 23 分贝（多数在 20–25） | 全程铺底：覆盖约 97%，几乎不留白；没人说话处抬 10 分贝；鼓点重得多 |
| 蛋解创业 | 口播 | 3 | 约 19 分贝 | 全程铺到底，结尾直接切 |
| 毕导 | 知识类 | 3 | 约 17 分贝 | 全程铺，停顿处只抬两三分贝 |
| 无穷小亮的科普日常 | 知识类 | 3 | 基本不用配乐 | 量到的只是现场声 |
| 房琪kiki | 生活 vlog | 3 | 约 12 分贝 | 音乐是主角，全程铺，说话时也只压两三分贝 |

只量了 3 条的只能看方向。对照某一位博主：`python3 musiclab/ml.py ref check out/某期 --like 小Lin说`。

要注意：

- **同一个方向里做法差很多**（毕导和无穷小亮都算知识类）。所以对标要落到具体博主，不要只按方向取平均。
- 抓来的音频只在本机缓存（`reference/cache/`），不进仓库，也不用进任何成片。进仓库的只有量出来的数字。
- 博主的配乐都标成「原声」，查不到曲名。这条路能学到的是**怎么用音乐**，学不到**用的哪首歌**。

## 现在还不行的地方

- **情绪判断靠标签，不靠听**。标签粗（约 20 个词），同一组标签的曲子分不出高下。下一步是给每首曲子算一个音频语义向量，用一句话描述去检索。
- **没有逐字稿时节点要人补**。接上剪辑流程的 `timing.json` 后，可以让 AI 读稿子自动标节点。
- **只选一首**。长视频（老师分享常见）按章节换歌还没做。
- **没有音效和环境声**。目录结构里留了 `kind` 字段，还没接来源。
- **速度自动检测偶尔差一倍**。有人工标的速度时用人工的。
- **评测集还没有**。需要十几二十条「公认配得好」的片子做基准，改算法时才知道是变好还是变差。现在靠 `rate` 一条条攒。

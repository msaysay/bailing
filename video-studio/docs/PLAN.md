# 视频生产全流程规划

2026-11-13 · 第一版

## 1. 结论

1. **做成「Agent + Skill + 脚本 + Remotion 工程」，不做成一个 App。** 两个对标都是这个形态：Agent 负责判断和写代码，脚本负责能被机器验证的部分（时间戳、对账、检查），Remotion 负责把每一帧画出来。先把这条线跑通，要不要包一层界面以后再说。
2. **画面底座用 video-shotcraft（Apache-2.0，已放进 `vendor/`），口播管线自己写。** 你给的两条对标成片都是口播解说片，最对口的其实是同作者的 video-talkcraft，但它是非商用许可，代码不能拿来做产品。它的方法可以学，下面第 4 节按它的思路重新设计。
3. **第一个里程碑是一条 60–90 秒、TTS 配音、单一风格的成片**，端到端走完十个阶段。组件库、第二套风格、数据回流都排在它后面。
4. **质量靠三样东西：真实素材、一套组件、写成规则的审美。** 这是 Fred 在自己的发布文案里反复讲的（「真实画面、真实数据、组件积木和审美手册」「组件、拆小步、把意见写成规则」「廉价的原因是加太多」），shotcraft 的审美准则也是同一个方向。

### 2.2 Fred 的流程（从分享包还原）

```
创意澄清 → 选题拆解 → 内容大纲 → 逐页逐字稿 → 画面规格（deck-spec）
   → 录音 → 人声处理 → 1.1 倍速 → ASR → 按实际声音粗剪 → 审片台听审 → WAV + SRT
   → 视频剪辑 Skill（组件库 + Remotion）→ B-roll 生成 → 封面
   → 最终 QC → 发布文案（依据成片字幕与章节时间点）→ 数据回流
```

值得照搬的做法：

- **两个大 Skill 用目录交接，不用聊天记录交接。** 内容生产和视频制作各管一段，中间是每期目录里的文件（`handoff-to-video.md`）。
- **逐字稿有硬约束**：3–5 分钟对应 1000–1300 汉字；每页只讲一个重点；开头给 3 个备选钩子并标推荐；写完统计字数、扫平台风险词。
- **开头钩子有选择顺序**：痛点/事故 → 结果前置 → 冲突纠偏 → 情绪共鸣 → 吊胃口；第一句是「具体对象 + 具体麻烦或结果 + 本期承诺」，18–32 个汉字；前 30 秒有固定结构。
- **音频以声音为准**：字幕重复不等于真的重说，听到了才剪；逐字稿是文字权威，ASR 只用来对时；技术测量通过、听审通过、用户认可是三个不同状态，分开记。
- **复刻别人的效果要立合同**：先记录参考视频的尺寸、帧率、关键动作时间，写清保留什么改什么，再用 Remotion 重建；所有动作由帧号驱动，不用真实时钟和随机数。
- **「平台说成功」不等于「看过了」**：生成类素材（B-roll、封面）下载后要实际看动作因果、人物一致性、手部和文字。

### 2.3 两条对标成片的画面

| | 《黄仁勋辞职》（竖屏 720×1280，5:52） | 《Token 到底是什么》（横屏 1280×720，5:28） |
|---|---|---|
| 风格 | 财经解说：黑底 + 金色强调 | 像素闯关游戏 |
| 画面来源 | 真实新闻画面和 B-roll 垫底，上面叠信息组件 | 全部代码绘制，没有实拍 |
| 组件 | 时间线、数据卡、公式卡、柱状图、天平对比、名单、人物卡、网页截图划线 | 固定主角、世界地图选关、关卡场景、HUD 道具栏、结算页 |
| 结构 | 顶部章节条贯穿全片；片中插一张自家 Skill 的宣传卡；片头片尾品牌页 | 每个概念一关；通关后回顾「装备栏 5/5」；结尾三连引导 |
| 字幕 | 中文 + 英文小字双语 | 单行中文，关键词变色 |
| 节奏 | 约 44 个镜头，平均 8 秒一个 | 约 40 个镜头，平均 8 秒一个 |

结论：**同一条生产线要能换「风格包」**。风格包 = 一套主题变量（颜色、字体、圆角、材质）+ 一组组件 + 一套镜头语法 + 片头片尾。流程、脚本、检查规则在风格包之间共用。

### 2.4 选题与节奏（64 条文案）

- 两个月发 64 条，基本日更；横屏为主，快讯和财经类用竖屏。
- 六个栏目：每周 GitHub 项目盘点、每周 AI 大事（1–2 分钟）、工具教程（Codex / Claude Code，3–18 分钟）、概念科普（像素游戏系列，5–8 分钟）、财经商业分析（6–10 分钟）、商单。
- 栏目化意味着**模板可复用**：周更栏目每期只换内容，这是日更能撑住的原因，也是我们该先做栏目模板而不是通用模板的理由。
- 标题是「主题 + 冲突或结果」；正文一段话说清本期讲什么，后面跟固定话题标签。

### 2.5 两个 Vincent 仓库的方法

**video-shotcraft（产品宣传片）**

- 流程：产品理解 → 视觉方向与定妆帧 → 功能到镜头映射 → 分镜 → 素材采集 → 逐镜头实现 → 声音设计 → 验收。
- 镜头卡是「配方 + 调好参数的 demo 源码」。用卡必须读 demo 源码，凭卡名自己重写等于放弃调校。
- 表现真实页面必须用真实截图（无头浏览器截 2 倍全页 + 元素坐标表），不手画假界面。
- 视觉语言从产品自身的设计系统里取，模板只继承运动，不继承皮肤。
- 一个镜头只讲一个动效；关键信息落定后要停留；有强节奏 BGM 时先做节拍分析再分镜。
- 渲染必须确定性：禁用 `Date.now()` 和 `Math.random()`，伪随机固定种子。
- 交付前派一个干净上下文的子 Agent 做独立终检，制作者自己不做首检。
- 成片后有浏览器工作台做多轨微调，可导出剪映工程。

**video-talkcraft（口播视频，只学方法）**

- **字幕句边界是全片时间锚点。** 配音先做字级时间戳，之后所有动效的时刻都从时间戳查，不手写秒数。
- 口播稿数字写汉字（时间戳按文本逐字对齐，阿拉伯数字对不上读音）。
- 真人录音先预剪（口水词、重说、长停顿），再做时间戳，顺序不能反。
- **逐句语义标注**：每句标「在做什么」（自我介绍 / 数据 / 对比 / 列举 / 引用 / 号召……封闭词表）和主次，选卡按语义过滤，素材清单也从标注生成。
- **SHOTBOOK**：每镜写素材行、选卡行、蒙皮行、版式行；节拍落成 `beats.json`；进实现前过一次机器对账。
- 新元素只在语义段落边界进场，不是一句一个；一个节拍一个主角，说完让位。
- 全片没有实拍或图片就是「讲 PPT」；网页素材要「拍」（滚动、巡游、放大、划线），不贴静态截图。
- **首镜先做先确认**：共性问题（蒙皮、字幕、相机幅度、音效电平）在第一镜就能看出来，做完再改是十几倍返工。
- 机器闸：静止段检测、词落点误差、镜尾保护带、音效电平、卡片保真度；之后才是人工审片。

## 3. 我们的全流程

十个阶段。每个阶段有明确的输入文件、输出文件和放行条件，产物都落在每期目录里，阶段之间只靠文件交接。

| # | 阶段 | 输入 | 输出 | 放行条件 | 谁确认 |
|---|---|---|---|---|---|
| 0 | 选题 | 想法、热点、往期数据 | `brief.md`：对象、一句话承诺、栏目、时长、画幅、风格包、事实红线清单 | 承诺能在成片里兑现；事实有出处 | **你** |
| 1 | 大纲与口播稿 | `brief.md`、调研资料 | `outline.md`、`script.md`（分段、3 个开头备选）、`script.json` | 字数达标；数字写汉字；风险词扫描通过；去模板腔 | **你** |
| 2 | 配音与时间戳 | `script.json`、录音或 TTS | `audio/full.wav`、`timestamps.json`（字级） | 每句对齐匹配度 ≥ 0.90；听过无爆音、截断、误读 | 机器 + 抽听 |
| 3 | 语义标注 | 稿子 + 时间戳 | `semantics.json` | 与时间戳逐字一致；词表封闭；每段至少一个主句 | 机器 |
| 4 | 分镜 | 标注、风格包、组件索引 | `SHOTBOOK.md`、`shots.json`、`beats.json` | 每镜有素材行和选卡行；节拍时刻全部由时间戳查得；版式不连续重复 | **你**（看分镜表） |
| 5 | 素材 | 分镜的素材行 | `assets/`、`sources.md`（来源与授权） | 文件都在盘上；实拍或图片镜头占比 ≥ 1/3；网页素材有坐标表 | 机器 |
| 6 | 实现 | 分镜 + 素材 + 组件 | Remotion 工程 `remotion/` | **首镜先渲给你看**，认可后再做其余镜头 | **你**（首镜） |
| 7 | 声音 | 成片时间线 | 音效清单、BGM | 音效比人声低约 12dB；同一帧最多一条 | 机器 |
| 8 | 渲染与验收 | 工程 | `out/final.mp4`、`qa/` 报告 | 机器闸全过；独立审片的严重问题清零 | 机器 + 子 Agent + **你** |
| 9 | 封面、文案、发布、回流 | 成片、字幕、章节时间点 | 封面图、发布文案、`publish.json`；发布后数据表 | 文案与成片一致；封面文字逐字核对 | **你** |

你需要出面的只有五处：选题、稿子、分镜、首镜、成片。其余由 Agent 连续推进。

### 每期目录

```
episodes/<期号_选题>/
  brief.md  outline.md  script.md  script.json
  audio/        full.wav  timestamps.json
  semantics.json  SHOTBOOK.md  shots.json  beats.json
  assets/       broll/  stills/  pages/  generated/     sources.md
  remotion/     src/  public/
  qa/           机器闸报告、审片报告、关键帧
  out/          final.mp4  cover.png  publish.md
  STATE.json    当前阶段、各阶段状态、待确认项
```

`STATE.json` 让流程可以中断后接着跑，也是以后做界面时的数据来源。

## 4. 实现方式

### 4.1 目录结构（目标）

```
video-studio/
  skills/        每个阶段一个 Skill（SKILL.md + references）
  scripts/       确定性脚本：对齐、对账、检查、渲染
  packages/
    core/        时间锚点、相机、让位、字幕、转场（与风格无关）
    components/  信息组件：时间线、数据卡、对比、列表、章节页、网页拍摄……
    styles/      风格包：finance-dark、pixel-quest……
  template/      新一期的 Remotion 工程壳
  episodes/      每期产物
  vendor/        第三方参考代码（不改）
  docs/
```

### 4.2 每个阶段用什么

| 阶段 | 做法 | 复用来源 |
|---|---|---|
| 0 选题 | Skill：先澄清再写 `brief.md` | `vendor/brainstorming`（MIT）改写成选题版 |
| 1 口播稿 | Skill：大纲 → 逐段稿 → 钩子备选 → 字数统计 → 风险词扫描 → 去模板腔 | 钩子与逐字稿规则自己重写（方法来自 Fred 分享包）；`vendor/humanizer-zh`（MIT） |
| 2 配音 | 两条路：真人录音，或 TTS | TTS 服务待定（见第 6 节） |
| 2 时间戳 | 自写脚本：ASR 出词级时间 → 与稿子逐字对齐 → 每句匹配度 | 自己实现；ASR 用 faster-whisper 或 FireRedASR（都可本机 CPU 跑） |
| 3 语义标注 | 自写脚本出骨架，Agent 填，脚本校验 | 自己实现，词表自定 |
| 4 分镜 | Skill + 对账脚本 | 格式自己定；镜头语法参考 shotcraft 镜头卡 |
| 5 素材 | Playwright 截全页 + 坐标；Pexels / Pixabay 取 B-roll 和图；可选 AI 生图生视频 | shotcraft `capture-template.mjs`；环境已自带 Playwright |
| 6 实现 | Remotion 4 + React；组件从 `packages/` 取 | shotcraft `assets/lib`（PageCam、Caption、DigitRoll、FlashCut 等）、`demos/` 各卡源码、`template/` |
| 7 声音 | Freesound 取音效（默认 CC0），记录来源 | shotcraft `sfx-source.py` 与 `sound-design.md` |
| 8 验收 | 机器闸脚本 + 抽帧 + 独立子 Agent 审片 | shotcraft `final-review.md`、`aesthetic-rules.md`；闸脚本自己写 |
| 8 微调 | 浏览器多轨工作台、剪映工程导出 | shotcraft `workbench/`、`jianying-export/` |
| 9 封面 | 生图 + 逐字核对文字 | 方法来自 Fred 封面包，自己重写 |
| 9 发布 | 先人工发；稳定后再接自动发布 | shotcraft `publish/upload_post.py` |
| 9 回流 | 后台导出表 → 校验 → 分析 | 方法来自 Fred 数据包，自己重写 |
| 对标学习 | 拉片：切镜检测、逐镜分析、反推提示词 | `vendor/fredtalk-shots`（MIT），可直接用 |

### 4.3 几条工程纪律（从一开始就定死）

1. **时间只有一个来源**：字级时间戳。组件拿「第几句第几个字」查时刻，不接受手写秒数。
2. **渲染确定性**：禁真实时钟和随机数，随机用固定种子。
3. **组件是中性的，风格包负责上皮**：换风格改颜色、字体、圆角、材质，不改时序、缓动、几何比例。
4. **真实素材优先**：能截真页面就不画假界面；讲数据就给出处。
5. **状态分开记**：机器通过、Agent 看过、你认可，是三件事。
6. **审美写成规则文件**：你每次说「这里不好」，都落成一条规则进 `docs/aesthetic-rules.md`，下期自动生效。从 shotcraft 的准则起步，逐步换成你自己的。

## 5. 里程碑

| 里程碑 | 做什么 | 完成标志 |
|---|---|---|
| M0 规划与学习 | 本文档、`vendor/` | ✅ 本次完成 |
| M1 最小闭环 | 一条 60–90 秒成片走完阶段 0–8：稿子 → TTS → 时间戳 → 简版分镜 → 5–8 个基础组件 → 字幕 → 渲染 | 你看到一条能看的成片；所有时刻来自时间戳 |
| M2 第一个风格包 | 按一个对标风格做全：15–20 个信息组件、章节页、片头片尾、网页拍摄、B-roll 垫底 | 一条 3–5 分钟成片，观感接近对标 |
| M3 质量闸 | 机器闸（静止段、词落点、音量、素材对账）、独立审片、首镜确认流程 | 同一稿子重跑，质量稳定，不靠运气 |
| M4 栏目化与外围 | 一个周更栏目模板（如每周 GitHub 盘点）、封面、发布文案、剪映导出 | 换一份内容，半天内出片 |
| M5 第二风格包与回流 | 像素闯关一类的全代码风格；后台数据回流到选题 | 两种风格可切换；选题有数据依据 |

M1 刻意做小：先证明「稿子进、成片出」这条线在我们手里是通的，再往上加东西。

## 7. 风险

- **Remotion 许可**：个人和小团队免费，公司使用可能要付费，商用前自己核对一次。
- **素材版权**：对标成片里的新闻画面、人物照片有版权风险。我们的 `sources.md` 每条素材都要记来源和授权，没有授权的不进成片。
- **本次没验证渲染**：我想在这台云端机器上渲一帧 shotcraft 模板做冒烟测试，被权限策略拦了（不允许安装并运行外部仓库的代码）。M1 开工第一步就是补这个验证。
- **只模仿会像赝品**：两个对标的风格辨识度都很高。组件和流程可以学，品牌色、主角形象、片头片尾要是你自己的。

# Typeless 拆解 & 百灵迭代清单（2026-07-24）

> 来源：typeless.com 官网 + 用户真机体验。目的：找出百灵下一阶段的优化点。

## 一、Typeless 做对了什么

### 1. 叙事：效率量化，一句话说清价值
- 主标语「Speak, don't type」，不讲技术讲收益。
- **量化对比**：键盘 45wpm vs 语音 220wpm，「Save 1 day/week」——用户一眼算出自己赚多少。
- 百灵现状：叙事在「懂你/知识库」（差异化），但缺「为什么用语音」的基础收益表达。

### 2. 首启引导（Onboarding）——用户点名最好的地方
- 注册后有一段首次使用引导，**让用户立刻知道核心功能是什么、怎么用**。
- 百灵现状：装完直接进托盘，新用户完全靠自己摸索——不知道要配 key、不知道能选知识库、不知道热键是哪个。**这是我们最大的体验缺口。**

### 3. 功能表达：全是用户视角的「小动作」
去口水词 / 去重复 / **改口自动修正**（说错改口只留最终意图）/ 自动排版 / 找词。每个功能一句话+动图。
- 百灵对照：这些能力我们基本都有（润色管线+口误修正），官网 demo 已体现，产品侧无需追。

### 4. 个性化可视化：Personalization Progress
- 把「越用越像你」做成**看得见的进度条**——用户感到产品在为自己成长。
- 个人词典：自动+手动加词，跨应用生效。
- 百灵对照：我们的学习闭环更强（改一次永久记住+知识库词库），但**学习成果完全不可见**——用户感知不到它在变聪明。

## 二、百灵迭代清单（按优先级）

| # | 迭代点 | 价值 | 成本 |
|---|---|---|---|
| 1 | **首启引导窗**：欢迎→配 key→选知识库→热键试说，4 步带新用户上手 | 🔴 最高（补最大缺口） | 中 |
| 2 | **官网补效率叙事**：Hero 加「说话 200 字/分 vs 打字 40 字/分」对比 | 高（获客转化） | 低 |
| 3 | **「它学会了多少」可视化**：托盘/设置里展示已学词数、修正条数（L4 语音记忆的雏形） | 高（强化护城河感知） | 低-中 |
| 4 | L2 风格画像（学你的语气用词注入润色） | 中（roadmap 原定） | 中 |
| 5 | 知识库沉淀回流 Obsidian | 中（roadmap 原定） | 中 |

## 三、首启引导设计方案（待拍板）

**触发**：首次启动（`settings.onboarded !== true`）；托盘菜单加「新手引导」可重看。

**形态**：560×640 无边框窗，宣纸墨朱同一套设计系统，顶部步骤指示（4 个朱砂点）。

**四步**：

1. **欢迎**：白描鸟 + 主标语「连着你的第二大脑，越说越懂你」+ 三行核心价值（它读你的知识库 / 专名自动写对 / 改一次以后都对）。
2. **配置密钥**：说明一句「识别和润色走你自己的 key，我只经手你的语音，不经手你的数据」+ key 输入框 + 「测试连接」按钮（复用 `settings:test` IPC）+ mimo.mi.com 申请入口链接。可跳过（跳过则润色关闭、仅 ASR 不可用提示？——不，无 key ASR 也不可用，给明确提示但允许跳过以后配）。
3. **连接知识库**：「选文件夹」按钮（复用 `kb:pickFolder`）+ 说明「选你的 Obsidian 库或任意笔记文件夹，本地索引不上传」+ 跳过选项（以后在设置里随时选）。
4. **按住试一下**：大字热键示意（右 Ctrl）+「按住它，随便说一句话」→ 真实录一次走完整管线 → 出字展示 → 「完成，开始用吧」。

**完成**：写 `onboarded:true`，关窗回托盘。

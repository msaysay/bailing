# 对标拆解 · 红顶双标题口播风

对标的是一条 3 分 32 秒的竖屏口播（得到 · 脱不花讲「短视频 AI 教练」）。一个人对着镜头讲，没有花哨的动效，靠四样东西撑住三分半钟：顶上两行不动的大标题、胸口逐行累加的字幕、五种画面硬切、几段手机截图。
这份文档记录量到的每个数。画面引擎 `studio/src/kit/redtop.tsx`、流水线 `scripts/redtop.py` 里的默认值都来自这里。对标截图在 `docs/reference/redtop/`。

## 一、整体数字

| 项 | 量到的 | 怎么量的 |
|---|---|---|
| 时长 | 211.9 秒，720×1280，30 帧 | 文件信息 |
| 语速 | 每秒 5.6 个字，全片超过 0.5 秒的停顿只有 7 处，最长 0.9 秒 | 语音识别的逐字时间 |
| 画面突变 | 31 次，平均 6.8 秒一次 | 机器按画面差异数的；同一画面里字幕变化不算 |
| 三类画面占比 | 人全屏 63%、黑底框（圆框加圆角框）13%、手机壳截图 23% | 每 0.2 秒分一次类 |
| 黑底框 | 10 次，每次 1.6 到 5 秒，平均 2.9 秒；大约每 20 秒一次 | 同上 |
| 人全屏时脸宽 | 占画面宽 25% 到 30%，两档：约 26% 和约 28.5%（差 1.1 倍） | 人脸检测 |

## 二、开头 11 秒的结构（最值得抄）

| 时间 | 画面 | 说的话 |
|---|---|---|
| 0 到 4.2 | 人全屏 | 「它是在全中国所有的短视频当中」 |
| 4.2 到 7.4 | 黑底圆框 | 「去给你找有可能你能对标的、同时有大流量的那种短视频」 |
| 7.4 到 11.2 | 人全屏，换了一个机位；**右侧出竖排名牌** | 「如果我想出我自己的第一条脚本，这应该怎么做」 |
| 11.2 到 14.2 | 黑底圆角框 | 「这个 AI 教练要从你要干什么开始」 |

1. **开头那句是从片尾挪上来的。** 0 到 7 秒这句话在 190 秒处原样又说了一遍：先把全片最有劲的一句结论放在最前面，再从头讲。
2. **开头 10 秒没有配乐**，是干声。
3. **名牌只出一次**：金句说完后的第一个正常镜头里出，停不到 4 秒，之后全片不再出现。竖排，白底小字写身份，蓝底大字写名字，在画面右侧、肩膀高度。
4. 没有片头、没有自我介绍。

## 三、常驻的两行标题

| 项 | 数值（占画面的比例） |
|---|---|
| 位置 | 第一行顶边在高度 8% 处，第二行在 15% 处，居中 |
| 字号 | 约画面宽的 10%（7 到 8 个字正好铺满六七成宽） |
| 颜色 | 第一行白 `#FFFFFF`，第二行金 `#FEBE17`，都有深棕色描边和投影 |
| 底 | 顶上一条暗红 `#4B1600`：到高度 13% 是实色，到 30% 渐隐到透明；黑底版式时渐隐到黑，圆框压在它上面 |
| 写法 | 第一行提问或痛点（「短视频没流量？」7 个字），第二行给反转（「你可能搞错了战场」8 个字） |
| 时间 | 第 0 帧就在，一直到结尾黑底之前，不动、不变 |

## 四、字幕

| 项 | 数值 |
|---|---|
| 位置 | 第一行顶边在高度 69% 处（胸口），往下累加，最多三行 |
| 字号 | 约画面宽的 8.4%，一行不超过 10 个字 |
| 颜色 | 白字深棕描边；重点词金 `#F4BA18` |
| 出法 | **逐行累加**：一句话拆成两三行，第一行先出，说到第二行时第二行加在下面，第一行不走；这句说完整堆清掉。每行出现时从左边带一点模糊滑进来，约 0.15 秒 |
| 重点词 | 平均每两行有一处金色：名词性的关键概念（「AI 教练」「大流量」「第一条脚本」「注意力的战场」）、数字 |
| 压在哪 | 全屏时压在胸口；黑底框时在框下面；手机截图时直接压在截图上 |

## 五、五种画面

| 画面 | 样子 | 什么时候用 |
|---|---|---|
| 人全屏 | 原片铺满 | 默认 |
| 人全屏（另一个景别） | 脸大 1.1 倍，或者换机位 | 每隔几秒、每个剪口换一次，盖住跳帧 |
| 黑底圆框 | 黑底上一个圆，直径是画面宽的 73%，圆心在高度 37% 处；框里脸宽约 21.5% | 短的、承上启下的句子（「第二个战场」「你不能告诉它」「那变成你之后你要怎么办呢」） |
| 黑底圆角框 | 宽 73%、高 42%，顶边在 17%，圆角约 5% | 和圆框换着用，约三次里一次 |
| 手机壳截图 | 背景是把原片虚化压暗；中间一台手机，屏幕宽约 60%，里面放截图或录屏；截图上用红框圈、黄色马克笔划 | 讲到具体操作、要给证据的时候。一次 2 到 14 秒，全片 6 段共 50 秒 |

切换全部是硬切，没有转场动画。切换点和音乐节拍没有对齐关系（切换点离最近一拍的中位距离 0.10 秒，随机也有 0.13 秒）。

## 六、配乐和声音

| 项 | 量到的 |
|---|---|
| 做法 | **一首曲子从头铺到尾**，中间不换、不停 |
| 什么时候进 | 开头金句是干声；第 10 秒左右（金句说完、正文开始）才进，用了大约 10 秒慢慢起到正常音量 |
| 音量 | 说话时配乐比人声低 **24 分贝**（很轻，只是垫着） |
| 速度和调 | 约 112 拍每分钟，D 大调附近，偏明亮 |
| 重点处压低 | 两处比平时再低约 8 分贝：90 到 100 秒（「这就是最容易犯的陷阱，我犯这个错误犯了三年」）和 170 到 180 秒（揭晓答案那句）。**最关键的一两句话，配乐让开** |
| 结尾 | 话说完配乐收掉；最后 2 秒黑底三行字，配一声明显的收尾音（比人声还响） |
| 音效 | 约三分之一的画面切换处有一声很轻的「唰」 |

人声和配乐是用 demucs 拆开量的，拆分不完美，分贝数有一两分贝的误差。

## 七、结尾

最后 2 秒：全黑，中间偏上三行米色发光字（引导动作，比如「低成本起号 高效率获客／《某某课》已上线／点击下方链接购买」），标题消失。

## 八、我们的实现和它差在哪

- **字体**：对标片是一款很粗的黑体，没认出具体是哪款。我们用阿里巴巴普惠体特粗（免费可商用），粗细接近，字形不完全一样。
- **换机位**：对标片有第二个机位（侧面）。我们只有一条原片，用放大 1.1 倍代替。
- **字幕左对齐的变体**：对标片换机位时字幕会靠左排，我们一律居中。
- **手机截图上的红框和黄线**：对标片是人工对着内容画的。我们支持在 plan.json 里写位置，但要 AI 看着截图填，不会自动找。
- **重点词**：自动只标英文词和数字，其余要 AI 按内容挑。
- 横屏原片会被裁成竖屏，脸会显得很大（试片就是这样），圆框里装不下肩膀。这种风格要竖屏原片。

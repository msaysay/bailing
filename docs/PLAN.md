# 项目完整规划

2026-11-13 · 第三版（第二版基础上：写入七条决定、补充三个组件库、渲染环境已验证）

## 1. 结论

1. **先做内容，再做产品。** Fred 的业务顺序是「自己账号持续出片 → 把出片能力拆成可卖的东西」。组件、选型表、交付标准都是从几十期实战里沉淀出来的，不是先设计出来的。我们照这个顺序走：先稳定产出一类片子，同一方法在几个题材上都有效了，再谈沉淀和变现。
2. **第一类内容定为商业分析短片**：把一段经营判断剪成一条看得懂的短片。画面路线对应 Fred 的「财经与商业」，素材以用户洞察、交易流程、脱敏经营证据为主。
3. **口播成片的主管线不用自己写了。** Fred 开源的 FredTalk 2.5 是 MIT 许可、可商用，里面有完整的「稿件 + 录音 → 逐段选组件 → 关键帧 → 整期成片 → 局部返修」流程、门禁脚本和审片台，已放进 `vendor/fredtalk/`。第一版规划里「自己重写口播管线」的部分作废，改成在它上面做适配。
4. **要自己做的是三样**：我们自己的风格（品牌、字体、配色，不能顶着 FredTalk 的角标出片）、财经商业路线的组件（Fred 这条线的 201 个组件在付费的 4.1 里，不在公开仓库）、以及选题写稿和数据回流这两头（公开仓库只管中间的剪辑）。
5. **每段画面的最小交付单位是四件套**：口播锚点 + 素材原件 + 关注区域 + 可渲染组件。这是你在对照测试里总结的，也正是 Fred 公告组件的做法（传截图尺寸、归一化目标框、相机与强调时间）。我们的组件接口按这个四件套设计。

## 2. 对标告诉我们什么

### 2.1 Fred：业务

一个动作解释全部：用自己的账号出片，再把做片的能力拆成可试看、可下载、可交付的产品。每条片同时是内容、是组件演示、是教程素材、是代剪案例。

| 客户想要 | 他卖什么 | 交付的本质 |
|---|---|---|
| 先看看有没有用 | 公开视频、公开组件、2.5 免费版 | 用结果获客 |
| 有人整理资料、能问问题 | 专属会员群 | 筛选 + 更新 + 轻反馈 |
| 会写会录，剪片最耗时 | 剪辑会员（三条路线 402 个组件） | 软件包，边界清楚 |
| 从题目跑到发布前 | 深度会员（24 个 Skill + 安装陪跑） | 软件 + 实施服务 |
| 系统学工具 | 课程（挂牌 ¥299） | 教学产品 |
| 直接要片 | 单期 / 包月 / 定制代剪 | 按结果交付 |

链条是「公开视频 → 样片和组件证明能力 → 微信咨询 → 激活码与资源库交付 → 更新、答疑、代剪」。成交价、付费人数、续费率、利润都没公开，**他的组件数、播放量、工时都不能当我们的预测**。

对我们的启发：

- 软件包能重复卖，但每个新用户带来安装和答疑；代剪每多一条都占审稿审片时间。两种生意的经济性不同，要分开算。
- 他按**内容类型**切产品（教程快讯 151、财经商业 201、像素闯关 50），不是按技术切。一条路线就是一类片子的完整打法。
- 「抢先 14 天」把同一批组件做成了会员权益和公开获客两用。

### 2.2 Fred：怎么做片

| 工序 | 机器做 | 人判断 |
|---|---|---|
| 选题与事实 | 搜资料、原文、数字、可播放素材 | 定题，选有讨论价值又能证实的角度 |
| 写稿 | 按账号口吻出大纲和逐字稿 | 改观点、语气、事实 |
| 配音与字幕 | TTS 或原声 → 粗剪 → 字幕 → 用最终音频定时钟 | 听人名、数字、重音、停顿 |
| 准备画面 | 录屏、公告截图、数据图、实拍、B-roll 分类入清单 | 何时看原文，何时用图解释 |
| 选组件 | 按语义、素材形态、运镜意图检索候选，核源码和参数 | 用哪个对象表达这句，哪里留白 |
| 渲染审片 | 关键帧 → 运动预览 → 动态、可读性、声音、接缝检查 → 分段返修 | 看懂了吗、节奏对吗，反馈指到秒 |
| 封面发布归档 | 封面备选、平台资料 | 选封面、最后提交 |

官网自述：约 8 分钟的片，人工约 30 分钟，AI 工序约 2 小时。这是作者陈述，没有失败重试和返修数据。

从公开仓库读到的关键做法（都在 `vendor/fredtalk/skills/fred-remotion-output/`）：

- **只复用认可过的组件，或在其上二创；默认禁止凭空原创画面。** 找不到合适组件就报告缺口，不许退成大字页。
- **每段先看候选再定画面**：写下这段「看得见的对象和动作」去检索，前三个候选用或不用都要写理由，门禁脚本会重算并拦截。
- **场景为本期重写**：高分的几期不是把组件原样串起来，而是拆出组件的动作、对象关系、几何，为本期内容和接缝重写；但字体、颜色、阴影、缓动等底层一律用统一 kit，不手写近似值。
- **整期简报先于代码**：逐句填「对象 → 变化 → 证据在哪 → 观众看哪 → 交给谁」，再填段间交接表。
- **先做一段对照，再铺全片；先关键帧，后动态。**
- **门禁只证明来源合规，不证明画面好**；技术通过、视觉认可、用户认可分开记。
- **没有最终录音只做到关键帧，不出整片**；时长不够加组件或剪短，不用慢推和定格凑。
- 成片后有 `motion_audit`（查慢推、纯滚动、定格）和 `readability_audit`（查字看不看得清）。

### 2.4 Vincent：video-shotcraft 与 video-talkcraft

- **shotcraft（Apache-2.0，已入库）**：产品宣传片。价值在 124 张镜头卡（运镜、转场、数据、光效、收尾）和 PageCam 这类「拍真实页面」的组件，还有动效工作台和剪映导出。用来补 Fred 公开库里少的数据类、运镜类镜头。

## 4. 系统长什么样

### 4.1 分层

```
选题与写稿（自建）        brief → 大纲 → 逐字稿 → 发布文案
        ↓ 文件交接
音频与字幕（fredtalk）    录音/TTS → 粗剪 → 最终音频 + SRT
        ↓
剪辑主管线（fredtalk 适配） 整期简报 → 逐段选组件 → 关键帧 → 整期 Remotion → 审片返修
        ↑ 取用
组件库（自建 + 借鉴）      kit（底层统一值）· 组件 · 风格包 · 目录与检索
        ↓
交付与回流（自建）         封面 · 发布 · 后台数据 → 下一期选题
```

### 4.2 目录（目标）

```
skills/        我们自己的 Skill：选题、写稿、封面、发布、回流；以及适配后的剪辑入口
scripts/       检索、门禁、检查、渲染的入口脚本
kit/           底层统一值：字体、颜色、阴影、缓动、字幕、角标、坐标映射
components/    我们认可入库的组件，每个带预览、参数说明、来源
styles/        风格包：biz-dark（商业分析）、之后的其他路线
library/       组件目录 catalog.json（检索的事实源）
episodes/      每期产物
docs/          规划、设计语言、审美规则、选型表
vendor/        第三方参考代码（不改）
```

### 4.3 每期目录与状态

沿用 Fred 的三段式，便于直接用他的脚本：

```
episodes/<期号_选题>/
  01_输入素材/     稿件、录音、截图、录屏、数据、sources.md（来源与授权）
  02_最终输出/     成片、封面、发布文案
  03_制作过程/     brief、大纲、逐字稿、整期简报、manifest、remotion 工程、审片记录
  STATE.json       当前阶段、各阶段三种状态（机器通过 / 助手看过 / 你认可）
```

## 5. 一期片的全流程

| # | 阶段 | 产出 | 放行条件 | 你出面 |
|---|---|---|---|---|
| 0 | 选题 | `brief.md`：对象、一句话判断、证据清单、时长、画幅 | 判断能被证据支撑；涉及经营数据已脱敏 | ✔ |
| 1 | 写稿 | 大纲、逐字稿（3 个开头备选）、风险词扫描 | 字数对得上时长；每段一个重点；数字有出处 | ✔ |
| 2 | 音频字幕 | 最终音频 + SRT | 重说和口误按实际声音处理；字幕与音频同版本 | 抽听 |
| 3 | 备料 | 素材清单：原文截图、数据图、流程图、实拍、录屏 | 每段有素材或明确「纯组件」；来源和授权登记 | |
| 4 | 整期简报 | 逐句动作表 + 段间交接表 | 每句答得出：对象、变化、证据、焦点、交给谁 | |
| 5 | 逐段建议 | 每段的候选组件、选用理由、参考画面 | 建议阶段门禁通过；全片组件不重复堆用 | ✔ 选方向 |
| 6 | 关键帧 | 用本期真实文字和素材渲的关键帧 | 关键帧阶段门禁通过；排版、可读性、遮挡自查 | ✔ 提意见 |
| 7 | 成片 | 1080p 预览 → 动态与可读性检查 → 正式版 | 两项检查通过；接缝逐处看过 | ✔ 看片 |
| 8 | 返修 | 只重渲受影响的段 | 意见指到段和秒，逐条关闭 | |
| 9 | 封面与发布 | 封面、标题正文、发布记录 | 文案与成片一致；封面文字逐字核对 | ✔ 提交 |
| 10 | 回流 | 三秒留存、完播、收藏、有效评论；每段选型与返工时间 | 数据进表，结论写回选题和规则 | |

阶段 2、4–8 用 `vendor/fredtalk` 的流程和脚本；0、1、3、9、10 自建。

## 6. 组件策略

1. **接口统一成四件套**：口播锚点（第几句哪个词触发）、素材原件（截图、图表、视频的原始文件和尺寸）、关注区域（归一化坐标框）、组件及其参数。换一条新闻或一份报表，只重算关注区域和锚点。
2. **先借后建，能用的都用**（你的决定）。来源优先级：我们自己认可入库的 → Fred 公开仓库的全部组件（含他参考别人成片复刻的）→ remocn / snapcn / remotion-bits（MIT）→ shotcraft 镜头卡（Apache-2.0）→ 新做。字体、音效、媒体同样能用就用。会员专享条目的源码不在公开仓库，拿不到。每个借来的组件在目录里记来源，万一有人主张权利，能按来源快速替换。
3. **商业分析路线首批组件**（按对标成片和 Fred 财经路线的画面组织反推，约 15 个）：
   - 证据类：原文聚焦（截图 + 高亮 + 压暗上下文）、网页巡游、引用卡
   - 数据类：单数字落定、柱状对比、折线走势、占比、公式拆解
   - 关系类：时间线、流程步骤、因果链、两方对比、人物或公司卡
   - 结构类：章节页、顶部章节条、片头、片尾
4. **入库有门槛**：只有在成片里用过、你认可过的画面才入库；同类需求第二次出现才提炼成公共组件。每个入库组件带预览视频、参数说明、适用场景、来源记录。
5. **先做横屏 1920×1080**（你的决定）。Fred 的公开组件多按横屏设计，正好直接用；竖屏要重排，不是等比缩放，放到 M6。
6. **底层值集中在 kit**：颜色、字体、字阶、阴影、缓动、字幕、角标只在 kit 定义一次，组件里不许手写近似值。换风格只动 kit 和风格包。

## 7. 质量怎么保证

- **门禁脚本**：选型有没有比较候选、来源是否合规、实际调用是否对得上选型（借用 fredtalk 的 `library_gate`、`validate_storyboard`）。
- **机器检查**：动态（慢推、纯滚动、定格）、可读性（字号与停留）、时钟（禁真实时间与随机数）、音量峰值。
- **人看**：关键帧逐张看，接缝每 4 帧拼图看；问题写到段号和秒数。
- **独立审片**：交付前派一个没看过制作过程的子 Agent 对照简报和审美规则审一遍（来自 shotcraft）。
- **规则文件**：你每次提的意见，判断出可复用的那部分写进 `docs/aesthetic-rules.md`，下期自动生效。本期修法和长期偏好分开记。
- **三种状态分开记**：机器通过、助手看过、你认可。

## 8. 实现与技术选型

| 环节 | 选型 | 说明 |
|---|---|---|
| 执行者 | Claude Code / Codex + Skill | 不先做 App |
| 画面引擎 | Remotion + React | 两个对标都用；公司商用前核对 Remotion 许可 |
| 剪辑管线 | `vendor/fredtalk` 的 `fred-remotion-output` | 阶段 A 原样用，阶段 B 起复制到 `skills/` 改成我们的 |
| 音频字幕 | `vendor/fredtalk` 的 `audio-subtitle-roughcut` | 自带本地审片台；云端 ASR 需自配密钥 |
| 配音 | 首测用你的录音；之后接火山引擎 TTS | 流程以最终音频为准，两种来源走同一入口 |
| 组件检索 | `vendor/fredtalk/scripts/catalog.py` + 我们自己的 `library/catalog.json` | 目录格式沿用，便于共用脚本 |
| 素材采集 | Playwright 截全页 + 元素坐标 | 已验证：`scripts/smoke/capture-roi.cjs` 算出的坐标直接喂给组件，高亮落位准确 |
| 补充组件 | `vendor/remocn`、`vendor/snapcn`、`vendor/remotion-bits`、`vendor/video-shotcraft` | 数据、对比、字幕、运镜、收尾类 |

## 11. 风险

- **许可**：Fred 仓库 MIT 只覆盖原创部分；复刻工程、字体、音效、媒体各有各的许可。talkcraft 非商用。Remotion 公司使用可能收费。
- **素材版权与脱敏**：新闻画面、人物照片要有授权；经营数据进片前必须脱敏，且在采集素材前就冻结口径。
- **像赝品**：流程和组件做法可以学，品牌、配色、人设、片头片尾必须是自己的。
- **公开仓库不等于完整生产线**：Fred 的选题、写稿、财经组件都在付费层，我们估工作量时不能按「他都开源了」来算。
- **复刻类组件的权利**：按你的决定直接使用。Fred 自己把这部分标为「权利未确认」，风险在原作者而不在 Fred；用于自己账号出片问题不大，将来若把组件打包对外卖，这部分要先剔除或重做。
- **只验证了单组件**：整期流程还没跑过，M1 会暴露真实卡点。
- **云端字体**：这台机器只有文泉驿一种中文字体，正式出片要装我们选定的字体。

# 约读书房 · 口播成片工作流设计

对象：约读书房的出镜人录一条横屏口播，我们自动出一条 1080×1920 的竖屏成稿。
依据：参考成片（4 分 39 秒，30 帧）逐段拆解，加上 `claude/dazzling-albattani-swasfh` 分支上的组件库和口播线（`talk-01` 到 `talk-04`）。

> **实现状态（2026-11）**：这份设计已经落地，操作说明以 `.claude/skills/frame-talk/` 为准。和下文不一样的地方：
> 版式引擎和卡片库是新写的（`studio/src/yuedu/`），没有改造旧组件；素材来源是「客户给 → 搜 → 生成卡片」三级；
> 客户素材里的未成年人肖像已有授权，不再单独拦；标题由助手出三组、用户选；转写文字必须经出镜人确认。

一句话结论：**不沿用现有口播线「每期写一份场景代码」的做法，改成「品牌包 + 一份剪辑决定表（JSON）+ 一个固定模板」**。给客户长期出片，每期只应该变数据，不应该变代码。现有的脚本和约三十个组件直接复用，版式引擎要新写一个。

## 1. 参考片拆解

### 1.1 整片不变的相框（必须照做）

```
y=0     ┌──────────────────────────┐
        │  纸纹底 + 淡彩书本碎片     │
250     │  从“碎片化”到“系统化”      │  标题第 1 行：宋体，深灰
343     │ ▓ 约读书房如何解决 ▓       │  标题第 2 行：黄底圆角条，白字
470     │ “阅读指导”的标准化难题？   │  标题第 3 行：宋体，深灰
555     ├──────────────────────────┤
        │                          │
        │   画面窗 1080×810（4:3）   │  人、素材、贴纸、字幕都在这里面
        │                          │
1368    ├──────────────────────────┤
1510    │ 单新杰 | 约读书房合伙人  ▣ │  署名条：绿色宋体名字 + 两行头衔 + 标志
1620    │  （留空，平台按钮区）       │
1920    └──────────────────────────┘
```

标题、署名条、纸纹底、标志全片不动。所有变化只发生在画面窗里。

### 1.2 画面窗里出现过的六种处理

| 代号 | 处理 | 参考片里的样子 | 出现时机 |
|---|---|---|---|
| P | 人，常规或推近 | 横屏口播铺满画面窗；强调句硬切推近（约 1.15），片尾推到约 1.4 | 默认状态 |
| K | 关键词贴纸 | 白色斜体大字，背后一道橙色笔刷从左往右刷出；贴在头的左侧或右侧 | 「名师难复制」「双师模式」「内容强管控」这类概念词第一次出现 |
| L | 并列清单 | 同样的橙刷字，一条条在头两侧叠出来（专注度、语意解码速度、逻辑推演能力） | 口播连说三个并列项 |
| S | 聚光对比 | 画面压黑，只留一个羽化的圆；大字两行，前半句白色、后半句橙色；底部字幕隐藏 | 「我们不再…而是…」「不是…而是…」 |
| R | 素材全窗 | 门店、课堂、培训现场、后台录屏铺满画面窗；竖版截图居中、两侧用自身模糊垫底 | 口播提到具体场景、系统、数据 |
| E | 收束金句 | 人推近，底部超大字分两拍出现（黄色「可复制的」→ 白色「阅读教育商业解决方案」） | 全片最后一句 |

字幕：贴画面窗底边，一次一短句（12 字以内），白字黑描边斜体；关键词放大并变黄。位置全片不动。

节奏（按每 4 秒抽帧估算）：素材约占三分之一，人约占六成，聚光约 5%；贴纸和清单全片六七处。

### 1.3 参考片的三个短板（我们要补的）

1. **后台录屏看不清**。「总部可以通过后台数据」那几段，整屏表格缩进 810 像素高的窗里，一个字都读不出来。
2. **素材一来人就没了**。连续两三个素材镜头时，人消失七八秒，口播变成了旁白。
3. **抽象的话没有画面**。「七天线上集训 → 线下考核 → 上岗」「可量化的增长曲线」这类结构性内容，只配了相关性不强的空镜。

## 2. 设计：哪些照做，哪些升级

### 2.1 照做（写进品牌包，模板锁死）
相框的全部位置和内容、标题三行结构、署名条、字幕样式和位置、橙刷贴纸、聚光对比、收束金句。

### 2.2 升级（新增三种处理，对应三个短板）

| 代号 | 处理 | 做法 | 解决 |
|---|---|---|---|
| C | 画中画（头像缩小） | 人缩成画面窗右上角的小圆（直径约 220，白边加一圈品牌绿细线），窗里其余位置给内容。进出用 0.4 秒缩放，不硬切 | 短板 2：要讲三秒以上的素材，人不离场 |
| M | 录屏放大 | 录屏只交代「这是哪一页」，橙色取景框标出一块，随后把这一块的数据重排成大字白卡 | 短板 1 |
| G | 手绘关键帧 | 纸面风格的图形卡占满画面窗：流程、闭环、数字、增长曲线。人以小圆留在角上，或离场不超过 4 秒 | 短板 3 |

高级感靠克制，不靠多：
- **全片只有四个颜色**：纸白、墨灰、品牌绿、强调橙（黄色只留给标题条和字幕热词）。手绘卡一律纸白底，不用深色玻璃卡。
- **字体三种**：标题和署名用思源宋体，字幕和贴纸用得意黑（天生斜体，开源可商用），卡片正文用 MiSans。
- **动效只用三个动作**：刷出、弹入、硬切。不用旋转、弹跳、闪白。
- **同一时刻窗里最多两层信息**（字幕算一层）。聚光和手绘卡出现时字幕隐藏。

### 2.3 每句口播选哪种处理

| 这句话在干什么 | 处理 |
|---|---|
| 提问、过渡、表态 | P |
| 抛出一个概念词（全片第一次） | P + K |
| 连说两到四个并列项 | P + L |
| 不是 A 而是 B、从 A 到 B | S |
| 提到具体场景，画面只需要「看一眼」（3 秒内） | R |
| 对着一个东西讲（报告、后台、教材），超过 3 秒 | C，内容是录屏时接 M |
| 讲流程、闭环、数字、趋势，而素材库里没有对应画面 | G |
| 最后一句 | E |

### 2.4 硬指标（机器检查，不达标回去改表，不调阈值）

- 人在画面里（P、K、L、S、C、E）不低于 70%；人铺满画面窗不低于 45%。
- R 单次不超过 4 秒，连续两个 R 之后必须回到人或转成 C。
- 同一种处理连续不超过 15 秒；平均 4 到 6 秒有一次变化。
- K 全片不超过 8 处，S 不超过 4 处，两次 S 间隔 40 秒以上。用多了就不是强调了。
- 贴纸和清单不压脸：只放在人脸框左右两侧，离脸框至少 40 像素。
- 每个剪口都要盖住：落在 R、C、G 里，或落在换处理的那一帧，或在那一帧硬切景别。
- 景别只硬切，相邻两次至少差 0.08。
- 同一条素材全片只用一次。

### 2.5 和现有规则不一样的地方（有意为之）

| 现有规则 | 这条线怎么办 | 原因 |
|---|---|---|
| 画面字不重复口播 | 贴纸、清单、聚光**可以**重复口播里的词；手绘卡和放大卡仍然只放口播里没有的信息 | 参考片的贴纸就是「把这个词钉住」，这是客户认的风格 |
| 一半以上时长垫真实画面 | 改为上面的出镜占比 | 这条片子靠人立住 |
| talkcraft 的 108 张卡可选 | **一张都不用** | 那批卡仅限非商用，这是给客户做的 |

## 3. 工作流

```
一次性：品牌包 ──┐
一次性：素材库 ──┤
                ▼
口播原片 → ①粗剪对齐 → ②剪辑决定表 → ③配素材 → ④渲染 → ⑤自查交付
              │            │ ✔人看        │ 缺素材清单        │ ✔人看
              ▼            ▼              ▼                  ▼
          timing.json   edl.json      edl.json 补全       成片 + 封面 + 文案
```

人只出面两次：看剪辑决定表、看成片。

### 第 0 步 · 建品牌包（一次）

`brands/yuedu/`：

| 文件 | 内容 |
|---|---|
| `brand.json` | 四个颜色、三种字体、相框各区的坐标、字幕字号、贴纸样式、小圆位置 |
| `plate.png` | 纸纹底图（向客户要原文件；要不到就从参考片取一帧修掉中间区域） |
| `logo.png` | 约读书房标志 |
| `speakers.json` | 每位出镜人的名字、两行头衔、常用机位的人脸位置。换人出镜只改这里 |
| `glossary.txt` | 专名表：约读书房、一间书房、双师模式、阅读指导师……识别结果先按它纠错 |
| `rules.md` | 客户提过的意见里可复用的那些，每期开工前读 |

### 第 0 步 · 建素材库（一次，之后持续加）

客户把门店、课堂、培训、后台录屏等素材一次性给过来，放 `brands/yuedu/library/`。

`scripts/library_index.py`（新写）：每条素材拆镜头，每个镜头抽一帧让模型写一句描述并打标签（地点、人物、动作、有无文字、横竖版），测人脸，登记进 `library.json`，同时记录「哪一期用过」。

两条规矩：
- 只用客户自己的素材。品牌片不去外面搜画面。
- **有未成年人正脸的镜头单独打标**，需要客户确认有肖像授权才进可用池。参考片里课堂镜头很多，这件事要在第一次合作时问清楚。

### 第 1 步 · 粗剪与对齐（全自动）

沿用 `talk-02-roughcut`，改三处：

1. **没有稿子**。出镜人是脱稿说的，所以识别结果按 `glossary.txt` 纠错后就是稿子；模型只改错别字和专名，不改用词。
2. **裁切窗是 4:3**。从横屏原片里取一个 4:3 的窗口，让脸的中心落在窗宽 55%、窗高 38% 附近（人略偏右，左侧留给贴纸；人偏左拍的就镜像处理坐标，不镜像画面）。输出 1440×1080，推近时不糊。
3. **字幕一行不超过 12 个字**（`align.py --max 12 --fps 30`）。

输出：`person.mp4`、`voice.wav`、`timing.json`、`cuts.json`、人脸框。

放行：对齐率不低于 0.85；音画时长差小于 0.1 秒。剪口多于每 10 秒一个时在报告里说明。

### 第 2 步 · 剪辑决定表（模型出，人确认）

这一步是整条线的脑子。模型读 `timing.json`、`cuts.json`、`library.json`、`rules.md`，按 2.3 的对照表和 2.4 的硬指标，输出一份 `edl.json`：

```jsonc
{
  "speaker": "shan-xinjie",
  "title": ["从“碎片化”到“系统化”", "约读书房如何解决", "“阅读指导”的标准化难题？"],  // 第 2 行进黄条
  "hot": ["规模化", "以人为本", "标准化复制"],        // 字幕里放大变黄的词
  "beats": [
    { "at": ["开场", "名师难复制"], "do": "K", "text": "名师难复制", "side": "left" },
    { "at": ["开场", "必须将"],     "do": "R", "clip": "store-opening-03", "dur": 3.2 },
    { "at": ["双师", "我们不再"],   "do": "S", "a": "我们不再依赖名师个人IP", "b": "而是构建了一套双师模式" },
    { "at": ["培训", "七天"],       "do": "G", "card": "FlowSteps",
      "props": { "steps": ["7 天线上集训", "线下实战考核", "通过才能上岗"] }, "person": "bubble" },
    { "at": ["数据", "后台数据"],   "do": "M", "clip": "backend-report-01",
      "focus": [120, 300, 640, 220], "rows": [["到课率", "…"], ["续费转化率", "…"]] },
    { "at": ["数据", "专注度"],     "do": "L", "items": ["专注度", "语意解码速度", "逻辑推演能力"], "side": "left" },
    { "at": ["结尾", "可复制的"],   "do": "E", "a": "可复制的", "b": "阅读教育商业解决方案" },
    { "at": 41.87, "do": "P", "zoom": 1.15, "why": "盖剪口" }
  ]
}
```

要点：
- **时刻不写秒数**，写 `[段名, 词]`，渲染时从 `timing.json` 取（沿用 `say()`）。只有盖剪口的那几条直接用 `cuts.json` 里的数。
- **标题**由模型出三组候选，每组三行、第二行不超过 9 个字（黄条放得下），人选一组。
- **放大卡里的数字只能来自录屏本身**，模型读不清的格子留空让人填，不编。
- `scripts/plan_check.py`（新写）在出表时就按 2.4 逐条检查，不达标不给人看。

同时生成一份给人看的 `版式表.md`（每行：时间、口播、处理、素材或卡片、备注）和抽样关键帧（每种处理各一张静帧）。人看的是这份表和这几张图，改也是改表。

### 第 3 步 · 配素材（自动，缺的列清单）

对每个 R、C、M：按这句口播的意思在 `library.json` 里找镜头，优先没用过的、有动作的、横版的；竖版截图自动走模糊垫底。

找不到时按顺序降级：改成 G（手绘卡）→ 改成 P+K → 保持 P。同时把缺的画面记进 `缺素材清单.md`，交付时一并给客户（「下次去门店顺手拍这五个镜头」）。素材库就是这么越用越全的。

### 第 4 步 · 渲染（全自动）

一个固定的合成 `YueduFrame`，输入是 `brand.json + speakers.json + timing.json + edl.json`。**每期不写代码**。

确实需要一张模板里没有的卡时，在这一期目录下放一个 `custom.tsx`，`edl.json` 里用 `"card": "custom:名字"` 引用。同一种卡被要了两次，就收进模板。

顺序：先出每个 beat 开始后 0.6 秒的静帧 → 机器查压脸和出框 → 整片渲染。改动只重渲受影响的段（`seg_render.py`）。

### 第 5 步 · 自查与交付

- `qc.py`：黑场、闪帧、停滞、响度（沿用）。
- `frame_check.py`（新写，由 `talk_check.py` 改）：只看画面窗那一块，统计各处理占比对照 2.4；检查标题条、署名条每一帧都在且没被遮。
- 联系表逐秒过一遍。
- 封面：标题区加一帧人物推近的画面，竖屏 1080×1440（接 `video-08-cover`）。

交付时说清：剪掉了哪几句、哪些素材待确认授权、缺素材清单、机器验证不了的部分（口型、剪口顺不顺、卡片出现早晚）。

### 回流

客户每条意见先判断：只针对这一期，改 `edl.json`；以后都适用，写进 `brands/yuedu/rules.md`；是专名识别错，加进 `glossary.txt`。

## 4. 组件库怎么用

### 4.1 直接复用

| 用在哪 | 现有的东西 |
|---|---|
| 识别、粗剪、对齐、人脸、自查 | `scripts/asr.py`、`roughcut.py`、`align.py`、`faces.py`、`qc.py`、`seg_render.py` |
| 时刻 | `kit/clock.ts` 的 `say()` |
| 运动曲线 | `kit/motion.ts` |
| M 录屏放大 | `paper` 组的 `DeckWindow`（录屏取景窗）+ `MacroCard`（放大卡）+ `FieldRows`（字段卡）。这一组本来就是纸面浅色风格，和相框最搭 |
| G 流程、闭环 | `flow` 组的 `FlowSteps`、`Ladder`；`paper` 组的 `LoopRing`、`CheckRows` |
| G 数字、趋势 | `charts` 组的 `KpiCards`、`LineChart`、`ProgressBars`；`paper` 组的 `StatGrid` |
| E 收束金句 | `paper` 组的 `HeadlineStack` |
| 片尾关注 | `paper` 组的 `BigFollow` 或 `talk` 组的 `FollowCTA` |
| 景别推近 | `talk` 组的 `ZoomPunch` |
| 字幕热词 | `talk` 组的 `KaraokeCaption` |

横屏组件放进 1080×810 的窗基本不用缩，这点比现有竖屏口播线省事。但所有复用的组件都要过一遍**换色**：改成纸白、墨灰、品牌绿、强调橙，去掉深色底。

### 4.2 改样式后用

| 处理 | 基于 | 改什么 |
|---|---|---|
| K 贴纸 | `KeywordSticker` | 换成橙色笔刷刷出加白色斜体字，去掉箭头 |
| L 清单 | `SideBullets` | 同上，条目沿头的一侧竖排，避开人脸框 |
| S 对比 | `StrikeReplace` / `MythFact` 的两拍节奏 | 外面加羽化圆形遮罩，改成白橙两色 |

### 4.3 新写

| 东西 | 说明 |
|---|---|
| `kit/frame.tsx` | 相框引擎：`FrameStage`（纸纹底、标题区、画面窗、署名条）、人在窗里的四种状态（铺满、推近、小圆、离场）及过渡、`FrameSubs`（字幕）、聚光遮罩、竖图模糊垫底。现有的 `kit/talk.tsx` 是按人铺满 1080×1620 写的，坐标体系不同，不改它，另写 |
| `templates/yuedu/` | `YueduFrame` 合成：读 `edl.json`，把每个 beat 分发给对应处理 |
| `scripts/library_index.py`、`plan_check.py`、`frame_check.py` | 见第 3 节 |
| Skill 四个 | `frame-00-brand`（建品牌包和素材库）、`frame-01-cut`、`frame-02-plan`、`frame-03-render` |

### 4.4 不用

- `vendor/video-talkcraft` 和 `studio/src/talkcraft/` 的卡：仅限非商用。
- `bulletin`、`bc` 两组：深色播报风，和纸面相框冲突。
- `Danmaku`、`ReactionFloat`、`Impact`：热闹型动效，和教育品牌的调性不合。

## 5. 给出镜人的拍摄要求

| 项 | 要求 | 原因 |
|---|---|---|
| 画幅 | 横屏 16:9，1080p 以上，30 帧 | 画面窗是 4:3，从横屏里裁 |
| 人的位置 | 坐在画面中间略偏右，脸宽占画面宽 10% 到 13% | 一侧留给贴纸和清单 |
| 取景 | 膝盖以上，头顶留一个头的高度 | 推近到 1.4 还不切头 |
| 背景 | 书架这类有内容但不动的背景 | 缩成小圆时还认得出是在书房 |
| 录法 | 一条到底；说错停一秒，整句重说 | 剪口少，整句才能干净剪掉 |
| 声音 | 领夹麦 | 字幕时间从声音里取 |

## 6. 落地顺序

1. 在组件库分支上开工：`kit/frame.tsx` 加 `YueduFrame`，先只做 P、K、S、R、E 五种（即参考片的全部），用参考片的口播音轨复刻前 30 秒，和参考片逐帧比。
2. 加 C、M、G 三种升级处理，同一段 30 秒出一个升级版，给客户二选一或混着选，定下风格。
3. 写 `plan_check.py`、`library_index.py`，用一条真实原片从头到尾跑通，记录每一步耗时。
4. 写四个 Skill，把流程固化。

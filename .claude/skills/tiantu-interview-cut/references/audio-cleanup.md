# 声音：剪口吃/气口、降噪、配乐

## 一、口吃、重复、语气词、气口 —— 必须剪干净

人物口吃、起头重说、“嗯/呃”、句间换气和长停顿**一律剪掉**，成片口播要像参考片一样紧。三层机制，前两层自动，第三层靠你：

| 层 | 抓什么 | 怎么抓 | 在哪 |
|---|---|---|---|
| 文字层 | 转写里写出来的重复和语气词：`我我我们`、`这个这个`、`我们的那个我们的`、`嗯` | `draft_script.py` 自动用 `[ ]` 标出，`[ ]` 内的字会被剪掉 | script.txt 第一列 |
| 声学层 | 转写**没写出来**的口吃（Whisper 会把“除、除、除了”直接写成“除了”）、起头重说、未转写的杂音 | `cues_from_script.py` 把语音按能量切成发声块：① 某块与后一块开头**听起来一样**（频谱相似度 ≥0.55）→ 重复，剪前一块；② 逐块二次识别，前一块的音节是后一块的开头 → 起头重说；③ 稿里没有的短促发声 → 剪 | 自动，日志里每处一行 `✂ … 口吃/重复` |
| 停顿 | 句间、句内超过 0.28 秒的停顿（含换气） | 压到 0.13 秒；剪点只落在能量谷底，不切音节 | 自动 |
| 复听校验 | 剪过头（吞字）或没剪净（残留） | 把剪紧后的声音整体再转写一遍，与稿子逐音节比对 | 输出末尾 `verify:` |

你要做的：

1. 看 `draft_script.py` 标出的 `[ ]`：是强调性的叠词（“非常非常”）就去掉括号保留；漏标的口头禅（“那个”“就是说”“然后”）自己加 `[ ]`。
2. 跑 `cues_from_script.py` 后**逐行读日志**：
   - `✂ … 口吃/重复 / 起头重说 / 语气词`：已剪，无需处理。
   - `? … 疑似重复，未剪`：相似度在临界区，没敢剪。结合上下文判断，是口吃就在 script 里用 `[ ]` 标掉对应的字，或把这半句整行删掉。
   - `verify` 里的 `少了 [x]`：可能误剪了真字 → 给那一行加第 4 列 `keep`（`原文 | 字幕 | 关键词 | keep`）后重跑。
   - `verify` 里的 `多了 [x]`：残留口吃/语气词 → 用 `[ ]` 标掉后重跑。
   - `[x] 听成 [y]`（同音/近音）多为识别波动，可忽略。
3. 反复到 verify 干净为止。**verify 不干净不许进入下一步。**
4. 输出里的标记：`✂` 硬剪口（删了内容，画面必须换镜头/盖素材）；`·` 微跳剪（只抽掉了 <0.7 秒的停顿或口吃，画面不处理，参考片也是这样）；`〃` 同一句字幕的后半段（字幕不会闪）。

局限（要如实告诉用户）：中间**完全没有停顿**的连读口吃（“我我我们”一口气说完）且转写没写出来的，声学层抓不到；这类只能靠 QC 的“slow line”警告和 verify 的“多了”来发现。参数 `--repeat`（默认 0.55，越低越敢剪）、`--pause`、`--gap` 可调。

## 二、降噪

`render.py` 自动处理人声，顺序：高通 80Hz → 降噪 → 压缩 → 去齿音 → 限幅，最后整体响度 -16 LUFS。

`plan.json` 里 `"audio": {"denoise": "auto"}`（默认）按实测信噪比选档：

| 档位 | 触发（auto） | 做法 | 适用 |
|---|---|---|---|
| off | 信噪比 ≥45dB | 不降噪 | 领夹麦、安静室内 |
| light | 32–45dB | RNNoise 语音模型，约 -14dB | 空调、轻微底噪 |
| strong | <32dB | 频谱降噪 + RNNoise，约 -20dB（测试片底噪 -41→-61dB） | 仓库风机、车流、嗡嗡声 |

- 渲染日志会打印 `voice: SNR xx dB -> denoise xxx`，QC 会对极吵的源（<25dB）提示人工听一下有没有“水声/金属声”。有的话降一档（`"light"`）。
- **原片本身带音乐时必须设 `"off"`**（降噪会把音乐搅坏），并提醒用户提供不带音乐的原片。
- 降噪只作用在人声上，B-roll 自带的声音一律不用。

## 三、配乐

参考片全程有一条轻、稳、中速、偏明亮的铺底音乐，比人声低约 13 LU，片尾无人声时抬 6dB，最后 1.5 秒淡出。

优先级：**用户给的曲子 > `bgm_match.py` 匹配 > `--synth` 生成的兜底氛围垫**。

```
python3 scripts/bgm_match.py -o bgm --mood light -n 3      # 匹配 3 首候选，写 bgm/candidates.json 和 CREDITS.txt
```

- 曲库：incompetech（Kevin MacLeod），约 1400 首纯音乐，**CC BY 4.0：可商用，但必须署名**。署名文字在 `bgm/CREDITS.txt`，交付时原样给用户，让他放进视频简介；不想署名就换自己的曲子。
- 匹配逻辑：先按情绪标签、速度、乐器筛曲库（排除阴暗/搞笑/人声/爵士等），再把前几首下载下来“听”——电平是否平稳（没有大起大落）、是否让出人声频段、开头是否拖沓——综合排序。
- 情绪按内容选：`light` 产品/业务讲解（默认，最接近参考片）｜`calm` 人物故事/理念｜`drive` 数据/实力｜`warm` 客户故事/服务。
- 把第一名写进 plan：`"bgm": {"src": "bgm/xxx.mp3", "src_in": 0.0}`；音量自动按人声对齐，一般不用动 `level`（默认 -13）。
- **给用户选**：成片渲染完后一键出多个配乐版本（不重渲画面，几秒一个）：
  ```
  python3 scripts/swap_bgm.py plan.json out/final.mp4 --all bgm/candidates.json   # final_A / _B / _C
  python3 scripts/swap_bgm.py plan.json out/final.mp4 --none                      # 无配乐版
  python3 scripts/swap_bgm.py plan.json out/final.mp4 --bgm 用户的.mp3 -o out/final_own.mp4
  ```
  交付 A/B/C + 无配乐版，并说明每首曲名；用户不满意就给曲子，用最后一条命令替换。
- 曲库连不上（网络策略未放行 incompetech.com）且用户没给曲子：`bgm_match.py --synth` 生成一条中性氛围垫，或交付无配乐版并说明。
- 不要从抖音/网易云等平台扒有版权的流行音乐烧进成片。

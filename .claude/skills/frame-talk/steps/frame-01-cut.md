
# 相框口播线 第 1 步 · 转写、确认文字、去口误、粗剪、对齐、声音

出镜人是录好了才给你的，没有稿子。所以**识别出来的文字就是稿子，而且必须让他确认一遍**。字幕、贴纸、卡片上的每个字都从这份稿子来，这里错了后面全错。

## 1. 入库和转写

```bash
python3 scripts/frame_ingest.py "<口播原片>" "episodes/<期号_选题>" --slug <期短名>
```
它输出 `03_制作过程/转写稿.txt`（带时间的分句）、`口误建议.md`（机器找到的语气词、口吃、重说）、`meta.json`（人脸位置、裁切参数），并打印粗剪要用的 `--vf`。有「提醒」（人脸太小、分辨率不够、人不在中间）就原样告诉用户，由他决定重拍还是将就。

## 2. 校对成稿 `script.txt`

通读 `转写稿.txt`，写出 `03_制作过程/script.txt`：

- 按内容分段，每段第一行写 `## 段名`（两到四个字，如 `## 开场`、`## 双师`、`## 结尾`）。后面取时间全靠段名，别用标点和空格。一条四五分钟的片子分五到七段。
- 加标点。字幕按逗号和句号断行，**一行超过 16 个字就在中间意思能断的地方加一个逗号**。
- 只改错别字和专名，不改出镜人的用词和语序。「啊」「呢」这类语气词保留（它们占时间，删了对不齐）。
- **稿子里只留最后保留下来的那一遍**。口吃、重说的那几个字不写进稿子（它们会被剪掉）。
- 数字按念法写不了的（「600」念「六百」）：写汉字，对齐才准。

## 3. 发给用户确认（不能跳过）

写 `03_制作过程/稿子确认.md`，并把内容直接贴给用户。格式照 `episodes/14_约读书房_样片/03_制作过程/稿子确认.md`，三部分：

1. **拿不准的词**：一张表，每行是「时间｜听到的｜我写成的｜为什么拿不准」。人名、机构名、产品名、数字、行业术语，只要不是百分之百确定就列进来。
2. **我改掉的错字**：听到的 → 改成的。让用户一眼能看出你改得对不对。
3. **全文**：分段的完整稿子。

用户改完，把改动写回 `script.txt`；专名和行业词的错，同时加一行到 `brands/yuedu/glossary.txt`，下次就不会再错。

用户没回复之前可以先往下做粗剪和对齐，但**不进第 2 步**。

## 4. 去口误和粗剪

先读 `口误建议.md`。机器找三种东西，每条标了「确定」或「待定」：

| 类型 | 机器怎么找的 | 你要判断什么 |
|---|---|---|
| 语气词 | 前后都有停顿的「呃」「嗯」 | 一般直接删 |
| 口吃 | 一到四个字紧挨着重复（「我们我们」「这个这个这个」） | 「常常」「看看」这类正常叠字已排除；「非常非常重要」这种有意的强调要留 |
| 重说 | 停顿之后开头的三个字，在前面 8 秒内出现过（说了半句停下来从头再说） | 删前面那一遍，留后面那一遍。排比句（「我们要…我们要…」）会被误报，要留 |

文件末尾给了一条现成的 `--drop` 参数（只含「确定」的）。把你认可的「待定」也加进去，不认可的「确定」拿掉。机器漏掉的口误（对着转写稿读出来的），自己补上起止秒数：从要删的第一个字的时间，到要保留的下一个字的时间。

```bash
E="episodes/<期>"; P="studio/public/<期短名>"; W="$E/03_制作过程"
python3 scripts/roughcut.py "$E/01_输入素材/口播原片.mp4" "$W/asr-原片.json" \
  --drop "<起止秒，如 7.55-10.48,70.8-71.7；没有口误就不写这个参数>" \
  --vf "<frame_ingest 打印的那串>" --fps 30 \
  --out "$P/person.mp4" --cuts "$W/cuts.json"
```
超过 0.7 秒的停顿会自动收紧到 0.35 秒，不用管。`cuts.json` 是每个剪口在成片时间轴上的时刻，第 2 步要把它们一个个盖住。
（Windows 的 cmd 不认 `\` 续行，把命令写成一行。）

## 5. 对齐

```bash
ffmpeg -y -i "$P/person.mp4" -vn -ac 1 -ar 16000 /tmp/cut16k.wav
python3 scripts/asr.py /tmp/cut16k.wav "$W/asr.json"
python3 scripts/align.py --script "$W/script.txt" --asr "$W/asr.json" --audio "$P/person.mp4" \
  --out-timing "$W/timing.json" --out-audio "$P/voice.wav" --max 12 --fps 30
```

## 6. 声音：降噪和配乐

```bash
python3 scripts/frame_audio.py "$E"
```
默认全自动：
- **人声**：切低频、降噪、轻压缩、去齿音、响度归一到 -16 LUFS。降噪档位按量到的底噪自动选（安静不降、一般用轻、吵用强），也可以用 `--denoise off|light|strong` 指定。强档会让人声略发闷，底噪不大时别用。
- **配乐**：`brands/yuedu/music/` 里有文件就用，没有就合成一条。人说话时自动压低，头尾自动淡入淡出。`--music off` 不加；`--music <文件>` 指定；`--mood warm|bright|calm` 选合成配乐的气质；`--music-db -27` 调音量（越小越轻，-30 几乎听不见，-24 偏响）。
- 时长一帧不变，不影响字幕时间。输出 `mix.wav`，`meta.json` 的 `voice` 自动指向它。

原片本身已经带了音乐的（比如拿成片当原片测试），用 `--denoise off --music off`，否则会把原来的音乐当噪声处理、再叠一层音乐。

这一步你听不到结果。交付时要说：降噪用了哪一档、配乐是哪一首或是合成的，请用户听一下人声有没有发闷、音乐会不会太响。

## 检查
- 每段对齐率不低于 0.85。低了多半是稿子和录音对不上（删了口误但稿子里还留着，或者反过来）。
- `voice.wav` 和 `person.mp4` 时长相差不到 0.1 秒。
- 从 `person.mp4` 抽一帧看：人在不在窗里、头顶有没有被切。
- 剪口多于每 10 秒一个，告诉用户这条原片口误偏多，成片会显得碎。

## 输出
`script.txt`（用户确认过）、`稿子确认.md`、`口误建议.md`、`person.mp4`、`voice.wav`、`mix.wav`、`timing.json`、`cuts.json`、`meta.json`。

## 放行条件
对齐率达标；音画时长一致；**用户确认过文字**；向用户报告了剪掉哪几句、降噪档位和配乐来源。

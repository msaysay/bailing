# 红顶双标题口播风 · 丢一条原片，出一条成片

对标片的拆解和每个数的出处：`docs/对标拆解-红顶双标题口播.md`。命令都在 `python3 scripts/redtop.py`。

**和用户说话的规矩**
- 大白话，不提脚本名和文件名。每次停下来，最后一句是他下一步要做什么。
- **环境你来装**，不让用户装东西：`python3 scripts/doctor.py --fix`，没装上的照它打印的命令你接着装。
- **要用户定的事集中在开剪之前，一次问完**（第 2 步）。开剪之后只在「看关键帧」「看成片」两处停。
- 你听不到声音、看不了动态：交片时把没法验证的地方（口型、节奏、配乐听感）如实告诉他。

## 一共六步

| 步 | 做什么 | 要用户做什么 |
|---|---|---|
| 1 | 收原片、转写 | 给一条竖屏口播原片 |
| 2 | **确认单**：标题、字幕稿、要剪的地方、开头金句、个人信息、结尾、配乐 | 打开一页网页，改完复制回来 |
| 3 | 粗剪 | 不用 |
| 4 | 排版式、配乐、出关键帧 | 看一张图，说行不行 |
| 5 | 渲成片、自查 | 看成片 |
| 6 | 发布包 | 挑封面和标题 |

## 第 1 步 · 收原片、转写

```bash
python3 scripts/doctor.py --fix
python3 scripts/redtop.py new <两位序号_主题> --video <原片>
python3 scripts/redtop.py transcribe <期名>
```
- 原片要求：**竖屏**、一个人对着镜头讲、有原声。说错了重说一遍就行，不用停机。横屏也能做，但会裁成竖屏、脸会很大，要告诉用户效果打折。
- 它会打印：字幕稿、机器找到的重录和口吃、语速、脸的大小。
- 用户还没给原片：只说一句「请把竖屏口播原片发给我」。

## 第 2 步 · 确认单（开剪之前，一次问完）

先自己做三件事，再出确认单：

1. **校一遍字幕稿**（`episodes/<期名>/字幕稿.txt`）：改明显的同音错字；按意思重新断行。规矩：
   - 一行不超过 10 个字。**逗号 = 同一句里换行**（下一行加在下面）；**句号 = 这句说完**（整堆清掉重来）。一句最多三行。
   - 在意思的停顿处断，不要把一个词劈开（「短视频／剪辑」可以，「短视／频剪辑」不行）。
   - 只改错字和标点，**不改意思、不加没说过的话**。拿不准的专有名词留给用户改。
2. **想三组标题**。第一行白字：提问或痛点，不超过 8 个字；第二行金字：反转或答案，不超过 9 个字。三组角度拉开（一组提问、一组反常识、一组直给）。只用口播里有的意思，不夸大。
3. **挑两句开头金句候选**：从后半段找最有劲的一句结论（8 到 25 个字，单独听也成立），提到片子最前面。对标片就是这么开头的。

```bash
python3 scripts/redtop.py confirm <期名> --titles "行一|行二;行一|行二;行一|行二" --hooks "候选一;候选二"
```
然后对用户说（原样）：

> 开剪之前有几样要你定。我做了一页「确认单」，在这一期的文件夹里，双击打开：
> 标题三选一、字幕稿直接在上面改错字、要剪掉的地方打了勾、再填一下你的称呼和结尾想放的字。
> 改完点底部的「复制给 AI」，粘贴回来就行。

- 用户的工具打不开本地网页：把确认单里的七项在聊天里**一条消息**列出来，让他一次回完。
- 他贴回来之后：把里面的字幕稿原样写进 `字幕稿.txt`（第一行加 `## 全文`），其余几项记下来，**不要再问**。
- 他填了要插的截图或录屏：问清每张「讲到哪句话时出现」。

## 第 3 步 · 粗剪

```bash
python3 scripts/redtop.py cut <期名> --keep-retakes --drop "<确认单里要剪掉的时间段>" [--hook "<他选的金句>"] [--denoise] [--grade]
```
- 没有要剪的就不写 `--drop`；用户没改过勾选也可以直接不带 `--keep-retakes`（默认剪掉机器确定的重录）。
- 两个字之间超过 0.45 秒的停顿会自动收紧（对标片几乎没有气口）。
- 看打印的「对齐率」：低于 0.85 的段，回去看字幕稿是不是和原声差太多。
- `--denoise` 录的地方吵才开；`--grade` 脸偏暗才开，开了要看对比图。

## 第 4 步 · 排版式、配乐、关键帧

```bash
python3 scripts/redtop.py plan <期名> --title "行一|行二" [--name 称呼 --role 身份] [--cta "行一|行二|行三"] \
        --hot "重点词,重点词,…" --key "最关键那一两句里的几个字" [--insert "截图.png@从这几个字~到这几个字"]…
python3 scripts/redtop.py music <期名>            # 用户说不要配乐：加 --off；他自己给了曲子：--track 曲子.mp3
python3 scripts/redtop.py stills <期名>
```
你要给的三样判断：

- **`--hot` 重点词**（金色）：通读字幕，挑名词性的关键概念和数字，平均每两行一处。不要整行都金，不要挑「的」「是」「我们」这类虚词。英文词和数字会自动标。
- **`--key` 关键句**：全片最要紧的一两句（那句让人「哦」一声的结论）。它会被放进黑底圆框，说这句时配乐再压低。
- **`--insert` 截图**：讲到具体操作、要给证据时用。没有素材就不加，不要编截图。

`plan` 会打印版式表。检查三件事，不对就直接改 `episodes/<期名>/plan.json` 再出图：
1. 黑底框是不是落在短的、承上启下的句子上（不要落在长句中间）；占比 10% 到 20%。
2. 人全屏有没有连续超过 20 秒不换景别的。
3. 截图上要圈的地方：在 `inserts[].marks` 里写 `{"at": 秒, "type": "box" 或 "hl", "x": , "y": , "w": , "h": }`（都是占手机屏幕的比例，0 到 1）。你要先用看图工具看截图，量出位置。

**必须用看图工具看 `out/关键帧.jpg`**：标题有没有超出画面、字幕有没有压住嘴或出框、圆框里脸是不是完整、名牌有没有挡脸、结尾三行对不对。然后把这张图发给用户：「这是套在你片子上的样子，可以吗？」

## 第 5 步 · 成片

```bash
python3 scripts/redtop.py render <期名>
```
- 机器自查里「亮度突变」报在进出黑底框的时刻是正常的；黑场、闪帧、画面停滞有内容才要查。
- 逐秒看 `out/qc/sheet-1fps.jpg`。
- 交片时说清：剪掉了哪几句、用了哪首配乐（要不要署名）、哪些你验证不了。
- 用户说「改第 X 秒」：改 `plan.json` 对应的那一处，重新 `render`；只改字不用重剪。

## 第 6 步 · 发布包（成片点头后主动做）

```bash
python3 scripts/redtop.py publish <期名>     # 第一次会生成 发布.json，你填好三个标题、简介、话题、提醒，再跑一次
```
用看图工具看「封面总览.jpg」，发给用户：「封面回 A、B 或 C；标题回 1、2 或 3。」

## 不能破的规矩

1. 不改出镜人的意思和用词，只删重录、口误、长停顿；删了什么要告诉用户。
2. 画面上的字只来自口播和用户给的信息；标题不夸大；截图不编造。
3. 配乐只用包里的（`music/`，不用署名）或用户自己给的；别人的成片、对标片里的音乐不能用。
4. 称呼、身份、结尾文字用户不给就不出，不替他编。
5. 没看过关键帧不渲整片，没看过每秒联系表不交片。
